## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Проблема
По сообщению пользователя, последнюю страницу материала невозможно закончить обычным переходом вперёд: следующей страницы нет, поэтому оставшиеся новые слова не обрабатываются как прочитанные. Нужен явный сценарий завершения урока.

## Ожидаемое поведение
На последней странице вместо стрелки вправо показывается галочка с понятным названием «Завершить материал». Нажатие открывает подтверждение «Завершить материал?» с ответами «Да» и «Нет» и пояснением, что оставшиеся новые слова текущей страницы будут отмечены известными. «Нет» оставляет пользователя в ридере без изменений. «Да» выполняет обработку последней страницы и сохраняет факт прохождения урока для текущего пользователя. Аналогичный тупик нужно исключить в режиме предложений на последнем предложении и в материале из одной страницы/одного предложения.

Семантика слов по ADR-0005: только оставшиеся new текущей страницы/предложения переходят в known; tracked, known и ignored не меняются. Автоматическое known не означает добавление на изучение в SRS; оно сохраняет существующие правила происхождения автоматически добавленных записей. Пропущенные диапазоны других страниц массово не обрабатываются. Undo последнего bulk-known остаётся доступным. Факт завершения урока относится к пользователю, а не к общему материалу.

## Необязательное расширение: экран итогов
Пользователь предложил рассмотреть страницу статистики после завершения: сколько слов было в материале, сколько известных и новых, сколько добавлено на изучение из этого урока, сколько дней читали. Сохранить как идею для согласования при проектировании; экран итогов не является условием исправления завершения.

Перед включением экрана определить: считать вхождения или уникальные словоформы; известные/новые на начало чтения или на момент завершения; для «дней чтения» — дни с фактическим чтением или календарный интервал, часовой пояс и поведение при отсутствии истории. Новые слова после bulk-known могут обнулиться, поэтому нельзя выдавать текущее состояние за исходное. Для «добавлено» отличать явное добавление на изучение в этом уроке от автоматически отмеченных known, учитывать провенанс FLQ-21; ignored не включать в known. Время чтения и streak не входят в этот запрос. Если понадобятся новые продуктовые решения, оформить ADR.

## Связанный контекст
FLQ-22 — согласованность прогресса ридера и карточки библиотеки; FLQ-23 — отдельная задача точности позиции чтения, не дублировать её; FLQ-21 — происхождение слов, добавленных в уроке; FLQ-8 — учёт прочитанных токенов. При проектировании определить поведение повторного открытия завершённого материала, связь undo с признаком завершения и сброс завершения при изменении текста/версии материала (FLQ-26).

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 На последней странице стрелка вправо заменена галочкой «Завершить материал»; на промежуточных страницах сохраняется обычная навигация. Управление доступно с клавиатуры и имеет локализованное название RU/EN.
- [x] #2 Нажатие галочки открывает подтверждение Да/Нет с объяснением обработки новых слов; Нет или закрытие диалога не меняет статусы слов, прогресс и факт завершения.
- [x] #3 После Да оставшиеся new текущей страницы переходят в known по существующим правилам bulk-known; tracked, known, ignored и пропущенные диапазоны других страниц не затрагиваются.
- [x] #4 После успешного подтверждения урок сохранён как пройденный для текущего пользователя, в ридере и библиотеке отображается согласованный завершённый прогресс; состояние сохраняется после перезагрузки.
- [x] #5 Undo последнего bulk-known доступен и после завершения; его влияние на признак завершения явно определено и согласованно отражается в ридере и библиотеке.
- [x] #6 Завершение работает для одной страницы, последнего предложения в sentence mode и при отсутствии new; материал без word-like токенов обрабатывается без ошибки и ложных счётчиков.
- [x] #7 Двойное нажатие и повтор запроса не дублируют завершение, словарные записи и прочитанные токены; при ошибке сохранения нет ложного успеха, пользователь может повторить действие.
- [x] #8 Завершение изолировано по пользователю; устаревшая вкладка после изменения версии материала не завершает новый текст и не применяет к нему старый диапазон.
- [x] #9 Регрессионные тесты покрывают подтверждение/отмену, обе формы чтения, статусы слов, undo, повторные запросы и ошибки; документация описывает завершение, повторное открытие и поведение при изменении материала.
- [x] #10 После завершения открывается локализованный адаптивный экран итогов; доступен повторно, позволяет продолжить чтение, вернуться в библиотеку и отменить завершение.
- [x] #11 Итоговый снимок корректно различает вхождения и уникальные слова, статусы до финальной обработки, явно добавленные на изучение слова/фразы и дни фактического чтения UTC; повтор, изменения словаря и другой пользователь не меняют сохранённые итоги.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Пользователь подтвердил постановку («Верно») и поручил реализацию («Приступай»).
1. Добавить регрессионные API и UI тесты завершения, отмены, идемпотентности, сохранения статусов и undo; зафиксировать исходные проверки.
2. Добавить completed_at/completion_action_id к ReaderPosition через миграцию 0018 и атомарный POST /reader/complete: проверка версии и финального фрагмента, блокировка позиции пользователя, существующий bulk-known без промежуточного commit, сохранение завершения. Повтор возвращает тот же action; undo снимает завершение, не откатывает факт чтения. Обычная синхронизация позиции сохраняет завершение. Изменение текста удаляет позицию и завершение по существующему FLQ-26.
3. Выдать завершение через reader_position и библиотеку; завершённый прогресс 100%, включая материал без слов. В ридере галочка открывает локализованный диалог Да/Нет; успешное завершение оставляет материал открытым, показывает статус и доступный undo; ошибки допускают повтор. Блокировать параллельную навигацию во время записи и hotkeys под диалогом.
4. Записать решения в ADR и документацию ридера. Проверить API на реальных PostgreSQL/Redis, UI тесты, миграцию, типы/линтеры/сборку, затем выполнить ревью. Экран итоговой статистики не входит в реализацию.

5. По дополнительному поручению пользователя добавить CompletionScreen и неизменяемый completion_summary в JSON payload операции. Выбирать словарные показатели одним SQL statement перед финальным bulk-known, читать дни после учёта фрагмента, возвращать снимок в POST и GET с ожидаемым action_id. Поддержать legacy null, повторное открытие, ошибки, новые завершения в другой вкладке и возврат фокуса. Документировать ADR-0015 и проверить регрессии/мобильную раскладку.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Последняя страница и предложение завершаются через галочку и подтверждение Да/Нет. Операция атомарно отмечает новые слова финального фрагмента известными и сохраняет личное завершение; доступны повтор, undo и защита от старой версии текста.

После завершения открывается адаптивный экран итогов RU/EN: объём текста, уникальные слова, распределение статусов перед финальной обработкой, явно взятые на изучение слова/фразы, дни фактического чтения UTC. Снимок сохраняется вместе с операцией, доступен повторно и не меняется при изменении словаря. Предусмотрены продолжение чтения, библиотека, отмена, legacy без данных, ошибки загрузки и обновление после действий другой вкладки. Решения описаны в ADR-0014/0015 и документации ридера.

Проверки: 494 backend-теста, 372 frontend-теста, итоговые API9/UI15, сборка, Ruff/ESLint и повторное ревью успешны. Визуальная проверка компонента выполнена на desktop и 390px. Pyright исходников без ошибок; полный Pyright имеет прежние ошибки старых тестов. Перед запуском всей FLQ-27 требуется миграция 0018 (`uv run alembic upgrade head` из backend); дополнительной миграции для экрана нет. Рабочая БД не менялась, коммит и merge не выполнялись.
