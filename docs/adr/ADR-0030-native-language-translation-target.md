# ADR-0030 — Родной язык определяет язык перевода

- Статус: Accepted; показ флагов уточнён [ADR-0031](ADR-0031-foreign-translation-flags.md) (2026-10-18)
- Дата: 2026-10-18
- Задача: FLQ-47; дизайн — `docs/superpowers/specs/FLQ-47-native-translation-language-design.md`
- Заменяет: [ADR-0011](ADR-0011-ui-language-translation-target.md)
- Уточняет: [ADR-0012](ADR-0012-ten-learning-languages.md) в части «UI и целевой
  язык перевода остаются EN/RU» — целевой язык перевода теперь задаётся этим ADR
- Связан с: ADR-0003, ADR-0004, ADR-0029

## Контекст

ADR-0011 сделал язык перевода равным языку интерфейса (EN/RU). Пользователь
хочет выбирать их независимо: интерфейс не должен определять язык, на который
переводятся слова, а набор языков перевода не должен ограничиваться языками
интерфейса.

## Решение

В профиле появляется **родной язык** — `user_profiles.native_language_code`.
Он определяет язык всех новых переводов: AI-перевод слов, фраз и предложений,
пользовательский перевод, Wiktionary-lookup, внешние словари (пара «язык
материала → родной язык»), переводы предложений в AI-упражнениях SRS.
`ui_language_code` (EN/RU) определяет только тексты приложения: интерфейс,
пояснения AI-чата, обратную связь упражнений, подписи грамматических тегов.

Каталог родных языков — 15 кодов: `en, ru, pt, es, fr, de, zh-Hans, ja, ar,
hi` (все изучаемые по ADR-0012) и `it, ko, tr, pl, uk` (языки, с которыми LLM
переводят особенно хорошо). Каталог — надмножество изучаемых языков.

Родной язык не может совпадать ни с одним изучаемым. Backend отклоняет такое
сочетание в онбординге, настройках и при добавлении изучаемого языка.

`preferred_translation_language_code` сохраняется для совместимости и
синхронизируется с родным языком. Legacy-поле `translation_language` в
запросе онбординга принимается и игнорируется.

Миграция: родной язык = прежний язык интерфейса, если он не входит в изучаемые;
иначе он пуст, и пользователь проходит онбординг, где родной язык обязателен.

## Сохранённые переводы

Сохранённые переводы, заметки, учебные тексты и ответы пользователя не
переписываются и не скрываются при смене родного языка. Каждый перевод
показывается с флагом своего языка. Там, где показывается один перевод
(ридер, словарь, карточка SRS, подсказка упражнения), выбирается основной
перевод на родном языке, а при его отсутствии — самый свежий основной перевод
на другом языке. Это отменяет правило ADR-0011 «не подставлять перевод другого
языка». Автоматический перевод сохранённого словаря на новый язык не
выполняется.

## Перенесено из ADR-0011 без изменений

- Изменение языка не меняет статусы или историю обучения. Удаление языка из
  списка изучаемых не удаляет связанные пользовательские данные.
- Язык перевода включён в промпт и его hash; клиентские ключи запросов
  различают пользователя и целевой язык. Контекстные подсказки не кэшируются в
  backend; аудит содержит только метаданные.
- Кэш переводов предложений изолирован по `(user_id, segment_id,
  target_language_code)`; старые строки без владельца не выдаются.
- При отключённом AI сохраняется существующее поведение без внешних вызовов.
- Раздел ADR-0011 «Настройки аккаунта и данные» (дневные цели, смена пароля,
  JSON export schema_version=1, удаление каскадом) остаётся в силе.

## Последствия

Пользователь может держать русский интерфейс и переводить на украинский или
наоборот. Wiktionary-пакетов для новых пар нет — lookup возвращает
`not_installed`, ручной перевод, AI и внешние словари работают. Словарь
пользователя может содержать переводы на нескольких языках; это видно по
флагам. Пара «язык материала = язык перевода» больше не возникает в
пользовательских сценариях.
