# ADR-0024 — Браузерное расширение-импортёр

- Статус: Accepted
- Дата: 2026-09-27
- Задача: FLQ-38; варианты выбраны пользователем.
- Связано с [ADR-0008](ADR-0008-auth-model.md) (модель аутентификации не меняется),
  [ADR-0016](ADR-0016-youtube-video-materials.md) (YouTube-импорт переиспользуется),
  [ADR-0006](ADR-0006-tech-stack.md) (стек и раскладка монорепо).

## Контекст

Сейчас материал попадает в Glosano только через диалог импорта: вставить текст,
загрузить `.txt`/`.md` или указать YouTube-ссылку. Чтобы учить язык по статье из
интернета, её нужно вручную скопировать, почистить от навигации и вставить.
Спецификация продукта (`docs/lingq-like-self-hosted-spec-2026.md`) называет
браузерный импортёр среди будущих интеграций. Референсы — LingQ Importer (отправляет URL и выделение на
сервер LingQ) и собственный проект пользователя Plucker (выделение статьи на
клиенте через Readability с ручной подстройкой).

Вопросы, которые надо было закрыть:

1. Как расширение аутентифицируется в self-hosted инстансе.
2. Где извлекается текст статьи — в браузере или на сервере.
3. Что сохраняется об источнике и в какую видимость попадает урок.

## Решение

**Второй клиент — браузерное расширение `extension/`** в монорепо. WXT +
React + TypeScript strict + Tailwind v4 + Vitest, Manifest V3, одна кодовая база
и две сборки — Chrome и Firefox. Раскладка ADR-0006 расширяется третьим
самостоятельным проектом со своим lockfile и path-filtered CI. Публикация в
магазины расширений не входит в решение.

**Аутентификация — существующая сессия браузера.** Пользователь логинится в
Glosano в том же браузере. Расширение ходит в API из background-контекста с
`credentials: "include"`, cookie `glosano_session` уходит автоматически.
Для мутирующих запросов расширение читает cookie `glosano_csrf` через
`cookies` API и отправляет её в `X-CSRF-Token` — тот же double-submit, что у
SPA. Доступ к хосту инстанса запрашивается в runtime (`optional_host_permissions`)
после того, как пользователь указал URL в настройках; постоянного доступа ко
всем сайтам у расширения нет. Бэкенд-auth, CORS и модель сессий не меняются,
API-токены не вводятся.

**Извлечение текста — на клиенте.** Расширение внедряет скрипт по клику
(`activeTab` + `scripting`): находит основную статью через Readability,
показывает её рамкой и даёт подстроить границы, либо даёт выбрать блоки кликом,
либо берёт выделение. Код picker'а портируется из Plucker (MIT, с сохранением
copyright). В урок уходит плоский текст с абзацами через пустую строку: Glosano
не рендерит markdown, и разметка превратилась бы в мусорные токены.

**YouTube — через существующий импорт.** На странице видео расширение передаёт
URL в `POST /api/lessons/import-youtube`. Субтитры по-прежнему получает сервер
(ADR-0016).

**Источник сохраняется, видимость — private.** `POST /api/lessons` принимает
необязательный `source {url, author, site_name}`; при его наличии версия
источника записывается как `source_type="url"` с `source_uri`, `author`,
`source_label`. Схема БД не меняется — колонки и значение `url` уже есть.
Расширение всегда создаёт private-урок: чужая статья без лицензии не попадает в
shared-библиотеку. Правка текста урока переносит поля происхождения в новую
версию источника, чтобы URL не терялся после редактирования.

## Отклонённые варианты

- **Персональные API-токены.** Работали бы без логина в браузере, но требуют
  новой сущности, Bearer-аутентификации, UI управления токенами и пересмотра
  ADR-0008. Для личного расширения в том же браузере это лишняя поверхность.
- **Серверное извлечение по URL (как LingQ).** Сервер не видит контент за
  логином и пейволлом, получает SSRF-поверхность и парсинг произвольного HTML.
  Пользователь не может поправить границы статьи.
- **Клиентское извлечение субтитров YouTube (как LingQ).** Хрупкая копия
  неофициального `youtubei` API; ADR-0016 уже решает задачу на сервере.
  Остаётся возможным fallback'ом, если YouTube начнёт блокировать сервер.
- **Сохранение markdown.** Требует рендеринга разметки в ридере и отдельного
  решения о токенизации — не нужно для v1.

## Последствия

- Расширение работает только при активной сессии Glosano в том же браузере.
  Истёкшая сессия показывается как «войдите в Glosano».
- SameSite=Lax cookie должны уходить в запросах из контекста расширения с
  host-permission. Это проверяется в обоих браузерах до основной реализации;
  если в Firefox это не так, вопрос о токенах возвращается отдельным ADR.
- Glosano получает третий фронтенд-проект, его CI и зависимости
  (`@mozilla/readability`, WXT).
- `LessonSource` впервые получает `source_type="url"`; UI библиотеки и ридера
  пока не показывает источник — это отдельная задача.
- Интерфейс расширения локализуется штатным `_locales`; в v1 только английский,
  выбора языка нет.
