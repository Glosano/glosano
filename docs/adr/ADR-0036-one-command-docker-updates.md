# ADR-0036 — Обновление Docker-установки одной командой

- Статус: Accepted
- Дата: 2026-10-21
- Задача: FLQ-50.7
- Уточняет ADR-0034 и ADR-0035: автоматическое обновление управляемой установки.

## Контекст

Локальная установка уже выполняется одной командой, но обновление требует ручного
скачивания Compose, бэкапа и миграций. Пользователю нужен сопоставимый по простоте
путь, сохраняющий аккаунты, прогресс, файлы и настройки на macOS, Windows и Linux.

## Решение

Каждый стабильный релиз публикует `update.sh`, `update.ps1`, `update-check.py` и
совпадающий Compose в общем SHA256-манифесте. Скрипты привязаны к целевому тегу;
`latest/download` выбирает последний стабильный релиз. Python нужен только внутри
уже установленного образа, не на компьютере пользователя.

Автоматический путь работает в каталоге установщика с `.glosano-install` и
неизменённым release Compose. Секреты и настройки берутся из сохранённого `.env`,
переменные окружения терминала не должны их подменять. Имя проекта и хранилища
не меняются. Проверка старого Compose по опубликованной контрольной сумме и
сравнение нормализованной конфигурации отвергают несовместимые изменения.
Внешний Redis, собственный Compose, Portainer и обновления инфраструктуры остаются
ручными сценариями. PostgreSQL/Redis при обновлении приложения не пересоздаются.

Порядок: проверка → скачивание образов → остановка API/worker → приватные снимки
PostgreSQL, app_data, Redis и старой конфигурации → миграция → запуск → readiness.
Копии получают уникальный каталог, манифест SHA256 и флаг завершённого бэкапа.
Бинарные файлы копируются через `docker cp`, без stdout redirection PowerShell 5.1.

Установщик и обновлятор разделяют `.install.lock`. До остановки создаётся durable
маркер `.glosano-update` со ссылкой на бэкап; фазы записываются в `status`.
До миграции ошибка приводит к запуску старого приложения. После возможного начала
миграции приложение остаётся остановленным, бэкап сохраняется, новые попытки
блокируются до явного восстановления. Автоматического отката схемы нет: он может
повредить данные или скрыть ошибку. Повтор на уже установленной версии проверяет
готовность без новых бэкапов; downgrade выполняется только через восстановление.

## Последствия и проверка

Нужны свободное место и короткое окно недоступности. Бэкапы не удаляются автоматически
и содержат персональные данные и секреты. Это защита обновления, а не замена внешнего
резервного копирования. Инструкция восстановления проверяет целостность и возвращает
все три хранилища к одной точке, затем запускает старый образ.

CI проверяет Bash на Linux/macOS, Windows PowerShell 5.1 и PowerShell 7, отказы и
повторные запуски, реальное обновление и восстановление Docker на amd64/arm64.
Публичная проверка релиза дополнительно обновляет предыдущую установленную версию
с аккаунтом, уроком и словарём через настоящий GHCR и release assets.
