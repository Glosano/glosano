# ADR-0029 — Внешние словари в карточке слова

- Статус: Accepted
- Дата: 2026-10-18
- Задача: FLQ-46; дизайн согласован с пользователем, детали §11 спеки
  (`docs/superpowers/specs/FLQ-46-external-dictionaries-design.md`) приняты
  автором.
- Связано с [ADR-0004](ADR-0004-dictionary-wiktionary-provider.md) (локальный
  словарь Wiktionary — не заменяется), [ADR-0011](ADR-0011-ui-language-translation-target.md)
  (язык перевода = язык интерфейса; FLQ-47 развяжет их, словари берут целевой
  язык из карточки), [ADR-0008](ADR-0008-auth-model.md)
  (удаление профиля каскадом).

## Контекст

Своего словаря у Glosano почти нет: Wiktionary-пакеты ставятся вручную и
есть не для всех пар, основной перевод в карточке даёт AI. Учащемуся нужен
быстрый способ перепроверить AI и увидеть слово в живых примерах (Reverso
Context). Открытый вопрос «Внешние словари в MVP» из `docs/ui/word_card.md`
§15 этим ADR закрывается.

## Решение

**Пара языков** = язык материала → язык перевода пользователя. Язык
материала — `content.language_code` урока (в `/vocabulary` — язык строки),
язык перевода — проп `target` карточки. Код словарей не читает язык UI
напрямую, поэтому FLQ-47 не потребует переделок.

**Встроенный каталог** (бэкенд, `modules/dictionary/external_catalog.py`):
Reverso Context, Google Translate, DeepL, Lingvo, Wiktionary — в этом порядке.
Каждый словарь сам знает коды языков сайта и поддерживаемые пары; формат ссылок
проверен на живых сайтах 2026-10-18, формат Reverso взят из конфигурации сайта.
Выбор:
- **Lingvo — только `{en, es, fr, de, zh} ↔ ru`.** `ptbr-ru` отдаёт 404, а в
  `pt-ru` нет португальского словаря.
- **Wiktionary через `index.php?search=`** на языке перевода: находит страницу
  с нужным регистром и вместо 404 показывает поиск.
- **Пара одного языка** (`ru → ru`): из встроенных только Wiktionary.
- Reverso не предлагается для `hi` и для пар вне его матрицы.

**Свои словари**: название и шаблон ссылки с `{word}`; коды языков пишутся
прямо в ссылке. Привязаны к текущей паре либо «для всех языков». Проверка
обязательна на бэкенде (`external_templates.py`), фронт повторяет её:
- только `http`/`https`; `{word}` хотя бы раз, другие фигурные скобки запрещены;
- `{word}` не в схеме, хосте, порту и userinfo (проверка подстановкой двух
  разных слов);
- ссылка до 500 символов, название 1–40 после trim, до 30 своих словарей на
  пользователя.

Слово подставляется через `encodeURIComponent`; для DeepL `/` в тексте
заменяется пробелом (`word_encoding = no_slash`): слэш ломает его ссылку, даже
будучи закодированным. Ссылки открываются с
`target="_blank" rel="noopener noreferrer"`. Шаблон, не прошедший проверку на
фронте, не рендерится.

**Список по парам**: у каждой пары `(source, target)` своя раскладка —
видимые словари по порядку и скрытые. Пока пользователь ничего не менял, видны
все подходящие встроенные, затем свои. Новый подходящий словарь (из обновления
каталога или свой «для всех языков») появляется видимым в конце уже
настроенной пары. Порядок меняется стрелками ↑↓.

**Хранение**: таблицы `user_external_dictionaries` (свои словари) и
`user_dictionary_layouts` (раскладка пары; элемент — `builtin:<id>` или
`custom:<uuid>`), миграция 0027. API `/api/dictionary/external`: `GET` списка
пары, `PUT` раскладки, `POST`/`PATCH`/`DELETE` своих словарей. Ряд собирается
на фронте: один запрос на пару, кэш TanStack Query, дальше ссылки строятся без
сети — поэтому работает и для фраз.

**Интерфейс**: ряд «Словари» в `WordCard` сразу под полем перевода, до
подсказок (слова и фразы, свёрнутая и развёрнутая карточки, скрыт для `ignored`); «Настроить ›» заменяет содержимое
карточки панелью настройки.

## Отклонённые варианты

- **Встраивание чужих сайтов** (iframe, popup, парсинг ответов): хрупко,
  часть сайтов запрещает встраивание. Только ссылка в новой вкладке.
- **Общий список для всех пар**: языковые пары слишком разные по поддержке
  словарей.
- **Настройка на странице `/settings/dictionaries` и шаблоны с `{lang}`**
  (прежний набросок): требует знать коды языков каждого сайта и уводит из
  карточки.

## Последствия

- Прежний `links.py` и поле `external_links` в `/api/dictionary/lookup`
  удалены.
- Обе таблицы входят в JSON-экспорт профиля (`identity/export.py`) и
  удаляются каскадом вместе с пользователем (ADR-0008). Свои словари видит
  только автор.
- Формат сайта поменялся — правится одна строка каталога; пользовательские
  раскладки не затрагиваются.
- Покрытие словарей неравномерно (например, в ru.wiktionary нет `火车`);
  это принято.
