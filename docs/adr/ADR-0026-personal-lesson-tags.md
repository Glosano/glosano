# ADR-0026 — Личные теги материалов

- Статус: Accepted
- Дата: 2026-09-27
- Задача: FLQ-39; варианты выбраны пользователем.
- Связано с [ADR-0024](ADR-0024-browser-importer-extension.md) (поле тегов в
  расширении), [ADR-0013](ADR-0013-material-editing-and-deletion.md)
  (владение и удаление материалов), [ADR-0022](ADR-0022-word-grammar-tags.md)
  (грамматические теги слов — отдельная сущность, не пересекается).

## Контекст

Материалов в библиотеке становится много, а найти нужный можно только поиском
по названию. Пользователь хочет раскладывать материалы по своим произвольным
меткам («новости», «подкаст», «B2») и фильтровать по ним библиотеку. Теги
задаются классически — одной строкой через запятую — при импорте из веба и из
браузерного расширения и правятся у уже добавленного материала.

Библиотека показывает свои уроки и shared-уроки инстанса. Отсюда главный
вопрос: чьи это теги — самого материала или пользователя.

## Решение

**Теги — личные метки пользователя.** Каждый пользователь вешает свои теги на
любой видимый ему урок, включая shared-урок другого владельца. Чужие теги
никому не видны. Модель — ярлыки Gmail: нет конфликтов на общих уроках и нет
вопроса о правах на правку.

**Хранение — одна таблица `lesson_tags(user_id, lesson_id, tag)`.** PK по
всем трём колонкам, индекс `(user_id, tag)`, FK на `users` и `lessons` с
`ON DELETE CASCADE`. Отдельной сущности «тег» нет: переименование, если
понадобится, — `UPDATE ... WHERE user_id = ? AND tag = ?`.

**Нормализация на сервере.** NFC → trim → схлопывание внутренних пробелов →
lowercase. Длина тега 1–40 символов, не больше 20 тегов на урок, дубли
схлопываются. Запятая — разделитель ввода, внутри тега её нет. Разбор строки
«через запятую» делают клиенты; сервер принимает массив и сам нормализует
и валидирует его.

**Фильтр — несколько тегов, семантика «И».** Список тегов для фильтра — теги
пользователя на видимых уроках текущего изучаемого языка.

## Отклонённые варианты

- **Теги как свойство материала (правит владелец, видят все).** Проще модель,
  но на shared-урок нельзя повесить свою метку, а метки владельца навязываются
  всем читателям.
- **Нормализованная пара `tags` + `lesson_tags`.** Даёт атомарное
  переименование и место под цвет/порядок, но это лишняя таблица и upsert при
  каждом импорте, а таких потребностей нет.
- **Массив `tags text[]` с GIN-индексом.** Фильтр «И» одним `@>`, но нужна
  строка «пользователь × урок», которой нет (`reader_positions` появляется
  только после открытия урока), и денормализация без выигрыша.
- **Автодополнение тегов при вводе.** Не нужно для первой версии.

## Последствия

- Удаление урока и hard-delete профиля удаляют теги каскадом; теги входят в
  JSON-экспорт профиля.
- Если владелец снимает `shared`, чужие теги на уроке остаются в таблице, но
  нигде не видны: все чтения идут через фильтр видимости. Если урок снова
  расшарят, теги вернутся.
- Будущая сущность «урок как группа материалов» (упомянута в FLQ-36) может
  строиться поверх тегов или отдельно — этот ADR её не предрешает.
