# ADR-0035 — Локальная Docker-установка без HTTPS

- Статус: Accepted
- Дата: 2026-10-21
- Задача: FLQ-50.5
- Уточняет ADR-0008 (Secure-cookie) и ADR-0034 (локальная поставка).

## Контекст

Пользователь выбрал приоритетный сценарий: готовый образ запускается на собственной
машине с Docker, интерфейс открывается в браузере без домена и сертификата.
Поддерживаются macOS, Windows и Linux. Native desktop-приложение остаётся отложенным.

Исключения браузеров для Secure-cookie на HTTP localhost неодинаковы: Safari такое
исключение не поддерживает. Нельзя обещать полноценную локальную установку, полагаясь
на это поведение. Переключение всей поставки в development mode не требуется.

## Решение

- Установка по умолчанию использует `http://localhost:8000` и публикацию API только
  на `127.0.0.1`. База, Redis и данные остаются в постоянных Docker volumes.
- Явная настройка `GLOSANO_LOCAL_HTTP=true` отключает только атрибут Secure у session
  и CSRF cookies. HttpOnly у session cookie, SameSite=Lax, пароль, серверные сессии
  и проверка CSRF сохраняются. Приложение продолжает работать с `GLOSANO_ENV=prod`.
- В этом режиме API принимает Host только `localhost` или `127.0.0.1`. Установщики
  отклоняют публикацию на сетевой адрес и несовпадение портов HTTP URL и bind.
  Docker-адрес клиента не используется: на разных ОС контейнер видит разные NAT-адреса.
- Default настройки приложения и общего Compose — `false`: существующий HTTPS
  сервер сохраняет прежнее поведение. Установщик явно сохраняет local mode в `.env`
  для HTTP localhost; для HTTPS сохраняет `false`. Переход между режимами — явное
  изменение конфигурации владельцем, а не эвристика по недоверенным proxy headers.
- Bash installer работает на macOS/Linux, PowerShell 5.1+ — на Windows. Нужны
  Docker Engine/Compose либо Docker Desktop с Linux containers. Ни WSL-терминал,
  ни Git, Python, Node.js или сборка приложения пользователю не требуются.
- Установщики используют один release Compose и совпадающий тег образа; проверяют
  SHA256, создают случайные секреты, не перезаписывают чужие файлы и сохраняют
  конфигурацию при повторном запуске. Администратор создаётся существующей CLI.
- Серверная установка и доступ с других устройств сохраняют HTTPS. Локальный
  HTTP не является поддержкой публичного HTTP-сервера или LAN-развёртывания.

## Последствия и проверка

Локальная установка не требует reverse proxy или сертификата и не зависит от
браузерного исключения для Secure-cookie. Docker должен быть запущен. Остановка
Docker останавливает приложение; обычный restart/redeploy не удаляет данные.

Проверяем auth/CSRF для HTTP localhost и HTTPS server, отклонение чужого Host,
сценарии отказа/повтора обоих установщиков, Windows PowerShell и PowerShell 7,
macOS/Linux Bash, реальный Docker stack и браузерный сценарий с WebKit.

Источник по браузерному ограничению: [MDN, Using HTTP cookies](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Cookies).
