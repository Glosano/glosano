# ADR-0033 — Импорт словаря из LingQ

- Статус: Accepted
- Дата: 2026-10-19
- Задача: FLQ-14 (FLQ-14.1 — CSV и ядро, FLQ-14.2 — API по токену)
- Дизайн: локальная рабочая заметка, в репозиторий не публикуется; решения и
  факты, на которые опирается этот ADR, собраны здесь
- Связан с: ADR-0001, ADR-0003, ADR-0005, ADR-0030, ADR-0032

## Контекст

Пользователь уходит с LingQ на Glosano и не хочет собирать словарь заново.
Нужен перенос слов и фраз с уровнями, переводами, тегами, примером, датой
следующего повторения и known-словами. Уроки и тексты не переносятся.

Источников два: API LingQ по ключу пользователя (карточки LingQ с уровнями и
датами повторения) и CSV-выгрузка LingQ (без уровней, дат повторения и
known-слов: в файле их нет). Один запуск импортирует один язык — язык открытой
страницы словаря.

### Факты об источниках

**CSV-выгрузка LingQ** (проверено на реальном файле: 2123 карточки, португальский).

- Заголовок `term,phrase,tag1…tag16,meaninglanguage1,meaning1,meaninglanguage2,meaning2`.
  Колонки разбираются по именам: число `tagN`/`meaningN` может меняться.
- Обычный CSV в UTF-8: кавычки, запятые и переводы строк внутри полей.
- Колонок уровня и языка изучения нет.
- Встречаются многословные термины (до 6 слов), термины с заглавной буквы,
  дубли тегов по регистру (`Noun`/`noun`), автотеги LingQ (часть речи, время,
  лемма), значения на языках вне каталога переводов (`sv`), значение без языка,
  пустые примеры и примеры с многоточиями.

**API LingQ** (сверено с живым ответом: аккаунт на португальском, 2123 карточки).

- `GET https://www.lingq.com/api/v3/{lang}/cards/?page=N&page_size=100&sort=alpha`,
  заголовок `Authorization: Token <ключ>`.
- Ответ `{count, next, previous, results}`; конец списка — пустой `next`, на
  странице за последней приходит 404.
- Ключи карточки: `audio`, `extended_status`, `fragment`, `gTags`, `hints`,
  `importance`, `last_reviewed_correct`, `notes`, `pk`, `readings`,
  `srs_due_date`, `status`, `status_changed_date`, `tags`, `term`,
  `transliteration`, `url`, `wordTags`, `words`, `writings`. Импорт читает
  `term`, `fragment` (пример), `status`, `extended_status`, `hints: [{locale,
  text}]` (переводы), три поля тегов и `srs_due_date`.
- Уровни LingQ 1–4 приходят как `status` 0–3, `extended_status` — `0` или
  `null`; Known — `status` 3 вместе с `extended_status` 3 (519 из 2123:
  503 слова и 16 фраз). Распределение `status/extended_status`: 0/0 — 127,
  1/0 — 270, 2/0 — 42, 3/0 — 496, 3/3 — 519, 0/null — 665, остальное — 4.
- Теги разложены по трём полям: `tags`, `wordTags` и `gTags`. CSV-выгрузка
  содержит их объединение (для «acho» в CSV `Adverb, Noun, Verb, achar, eu,
  presente, verbo`, а `tags` в API один даёт только `achar, eu, presente,
  verbo`).
- `srs_due_date` вида `2024-02-09T09:41:15.849817` без таймзоны разбирается без
  ошибок на всех карточках (диапазон 2022-05 … 2026-09); импорт считает её UTC.

## Решение

### Маппинг уровней

- Уровни LingQ 1–4 → `tracked` с `confidence` 1–4.
- Known в LingQ → `known`.
- `ignored` из LingQ не приходит и при импорте не создаётся.
- CSV уровня не содержит: все новые items получают уровень, выбранный
  пользователем (по умолчанию `tracked`, `confidence` 1).

### Слово или фраза

Решает наш токенизатор уроков с учётом языка, а не пробелы. Нормализация —
существующие `normalize_token` и `normalize_phrase`; ключ совпадает с ридером,
в том числе для `zh-Hans` и `ja`. Одно слово → `token_items`, 2–8 слов →
`phrase_items` (`display_text` = исходный термин), больше 8 слов или пустой
результат нормализации → запись пропускается с причиной в отчёте. Лемм и
морфологии нет (ADR-0001): лемма LingQ — просто текст тега.

### Что переносит импорт по токену

Текущая реализация читает только карточки LingQ (`/api/v3/{lang}/cards/`).
Слова, которые пользователь отметил known прямо при чтении в LingQ, карточками
не являются и не переносятся; known-слова попадают в Glosano, только если у
них есть карточка со статусом Known. Есть ли у LingQ эндпоинт known-слов, не
проверено. Импорт known-слов — отдельная задача FLQ-14.4; её решают после
проверки API вживую.

Поэтому вкладка называется «По токену (с уровнями)», а не «полный перенос», и
прямо говорит, что known-слова из чтения пока не переносятся — только карточки.
Счётчик отчёта `known_words` — это новые known-слова, созданные импортом.

### Конфликты: режимы `keep` и `update`

- `keep` не меняет статус, `confidence` и review item существующего item.
- `update` выставляет их из LingQ напрямую, в том числе с понижением
  (`known` → `tracked 2`). Запрет ADR-0005 на переход `known` ↔ `ignored`
  относится к действиям в ридере, а не к переносу данных. Review item
  `tracked`-слова получает начальное состояние SM-2 и `due_at` из LingQ.
- Переводы, теги и пример добавляются в любом режиме, если их ещё нет. Заметка
  пишется только при отсутствии заметки.
- CSV-импорт уровень существующих items не меняет никогда: в CSV уровня нет, и
  «обновить» значило бы массово проставить всем один уровень. Выбранный
  уровень получают только новые items.
- Существующий item считается обновлённым (`updated_items`), только если импорт
  его действительно изменил: статус, `confidence` или review item, либо добавил
  перевод, заметку или тег. Повторный запуск без изменений в LingQ даёт 0.

### Дата повторения

`srs_due_date` из LingQ переносится в `review_items.due_at` для `tracked`;
остальное состояние SM-2 инициализируется как у нового item. Дата в прошлом —
слово сразу в очереди повторения. Если даты нет, `due_at` = сейчас.

### Обращение с токеном LingQ

Токен — только аргумент функции в памяти процесса. Он не попадает в БД, Redis,
очередь Taskiq, логи, тексты ошибок, `repr` объектов, отчёт и JSON-экспорт.
Импорт идёт внутри процесса `app-api` (asyncio-задача), а не через Taskiq:
иначе токен пришлось бы передать через брокер. Если сервер перезапускается
посреди импорта, задача помечается `interrupted`, повторный запуск безопасен.

Состояние задачи — статус, счётчики и отчёт — хранится в таблице
`vocabulary_import_jobs` без токена. У пользователя одновременно не больше одного
выполняющегося импорта (уникальный индекс по `user_id` при `status = 'running'`).
Отчёт хранит до 500 issues; остальные не теряются молча — их число лежит в
`issues_dropped`, и окно импорта пишет, сколько ещё не показано.

Интерфейс следит за запущенным импортом на уровне приложения, а не страницы
словаря: опрос и обновление словаря по окончании продолжаются, даже если
пользователь ушёл со страницы. Если опрос не удался, состояние импорта
считается неизвестным, а не проваленным.

### Пометка `import_source`

Новые items получают `added_by = 'user'` (видны в словаре по умолчанию) и
`import_source = 'lingq'`. Существующим items `import_source` не ставится.
Items с `import_source IS NOT NULL` не входят в статистику «новых слов за
сегодня»; повторения по ним идут как обычно.

### Переводы вне каталога

Локаль LingQ приводится к каталогу ADR-0030 по базовому языку (`zh-cn` →
`zh-Hans`, `pt-br` → `pt`). Перевод на язык вне каталога (например, `sv`) не
сохраняется: в отчёт идёт issue `translation_language_unsupported`, сама
карточка импортируется. Перевод без языка получает родной язык пользователя.
Значения сверх лимитов (перевод 512, тег 64, заметка 4000 символов)
пропускаются с issue `translation_too_long` / `tag_too_long` / `note_too_long`.

## Проверено вживую и что осталось

Живой запуск (FLQ-14.2, Task 10) подтвердил решения этого ADR:

- кодировка уровней (`status` 0–3, Known = `status` 3 + `extended_status` 3) и
  разбор `srs_due_date` работают как заложено, маппинг не менялся;
- теги лежат в трёх полях, поэтому импорт берёт их объединение (`tags`,
  `wordTags`, `gTags`; точные дубли убираются, регистронезависимое слияние — в
  ядре), как и CSV.

Остаётся открытым:

- у карточки есть поле `notes` (собственная заметка пользователя); сейчас
  импорт его не читает, заметкой становится `fragment`. Возможное
  продолжение;
- эндпоинт known-слов, не являющихся карточками, по-прежнему неизвестен. Сейчас
  такие слова не переносятся, и UI прямо говорит об этом; импорт known-слов —
  FLQ-14.4 (черновик);
- код китайского (`zh-Hans` → `zh`) не проверен: живая проверка шла только на
  португальском. Остальные коды языков изучения тоже не сверены.

## Последствия

- Повторный запуск не создаёт дублей; битые записи не останавливают импорт, а
  попадают в отчёт.
- Перезапуск сервера прерывает импорт по токену: токен нигде не хранится, поэтому
  «досинхронизировать» нельзя, только запустить заново.
- Новая колонка `import_source` и новая таблица входят в JSON-экспорт
  пользователя; токена там нет по построению (поля экспорта — allowlist).
- Исходящих запросов к LingQ администратор отключить не может; без выхода в
  интернет импорт по токену завершается понятной ошибкой.
