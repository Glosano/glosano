# ADR-0034 — Готовые Docker-релизы и подготовка базы при запуске

- Статус: Superseded частично: локальная HTTP-поставка — ADR-0035; остальные решения действуют.
- Дата: 2026-10-21
- Задача: FLQ-50.2
- Уточняет: ADR-0006 (поставка); ADR-0008 (настройки регистрации в готовой поставке)

## Контекст

Сборка приложения на сервере и отдельная команда миграции мешают первому
запуску и использованию Portainer. Пользователь согласовал готовые образы,
установку одной командой и Portainer Docker Standalone. Desktop отложен.

## Решение

- Публичные образы GHCR выпускаются для amd64 и arm64 с неизменяемыми тегами
  `vX.Y.Z`. API, worker и интерфейс принадлежат одной версии.
- `deploy/compose.yaml` — общий контракт пользовательской поставки без сборки.
  Корневые Compose-файлы сохраняют сборку из исходников и dev-режим.
- Одноразовый сервис `migrate` применяет миграции до API и worker. Alembic
  удерживает PostgreSQL advisory lock на протяжении запуска; конкурентные
  запуски сериализуются, время ожидания блокировки ограничено.
- `/health` проверяет живость API; `/health/ready` — PostgreSQL, точную ревизию
  схемы из образа и Redis. Worker начинает запуск после готовности API.
- Приложение по умолчанию публикуется только на loopback. Для других устройств
  нужен HTTPS reverse proxy. Production cookies и CSRF не ослабляются.
- В готовой поставке публичная регистрация по умолчанию закрыта; администратор
  создаётся CLI. Общий default настройки приложения из ADR-0008 не меняется.
  AI выключен; словари устанавливаются только явным действием владельца.
- Обновление — действие владельца: скачать образы, остановить API/worker,
  сделать бэкап, применить новую схему, запустить новую версию. Обновление
  образа автоматически работающим внешним updater-ом не поддерживается.
- Откат после изменения схемы требует восстановления бэкапа вместе с прежней
  версией приложения. Смена одного тега не является откатом базы.

## Последствия

Чистая установка не требует ручных миграций. Успешный запуск контейнера ещё
не подтверждает готовность приложения. Выпуск поддерживает Docker Compose
v2.20+ и Portainer Docker Standalone; Swarm не входит в контракт. Владельцу
по-прежнему нужны Docker и HTTPS-прокси для сетевого доступа.
