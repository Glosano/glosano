# Свободный AI-чат с контекстом абзаца — FLQ-30

Продуктовый объём уточнён пользователем 2026-09-19: сначала открытый диалог
по тексту. Упражнения отложены. Решение записано в [ADR-0020](../adr/ADR-0020-inline-chat-quotes.md); формат ответа
уточнён в [ADR-0021](../adr/ADR-0021-plain-text-chat-replies.md).
Реализация находится в `codex/flq-30-ai-chat`. Карточки новых цитат заменены на fenced-текст в поле сообщения;
ветка сохранена без push/merge.

## Пользовательский сценарий

При наведении на абзац слева появляются плюс по центру высоты видимого текста
и тонкая серая линия во всю высоту абзаца между плюсом и текстом; при наведении
на плюс проявляется круглая подложка. Кнопка открывает чат и прикладывает
весь исходный абзац прямо в текст текущего черновика между тройными обратными
кавычками. Отдельная карточка нового вложения не показывается. В режиме страницы можно добавить
несколько абзацев; в режиме по предложению — весь абзац текущего предложения.
Если страница показывает только часть абзаца, в цитату входит полный абзац.
Кнопка доступна с клавиатуры и на сенсорном экране; её появление не сдвигает текст.

Текст вопроса сохраняется, одинаковый блок не добавляется повторно. Пользователь
редактирует или удаляет цитату прямо в поле. Модель получает текущий видимый
текст без скрытого устаревшего вложения. Старые неотправленные вложения
безопасно преобразуются в fenced-текст; отправленная история остаётся неизменной.
Если перенос не удался, вопрос остаётся редактируемым: доступны повтор и явное
удаление только старых цитат без потери текста вопроса. Пока цитата
готовится, отправка её черновика заблокирована, включая уход в другой чат и
возвращение. Другие черновики остаются доступны. Наведение и добавление не
запускают модель: пользователь явно отправляет непустой вопрос.

Выделение текста сохраняет словарный сценарий с лимитом восьми слов. Карточка
слова предлагает дополнительный переход к чату с полным абзацем в поле сообщения. Чат не меняет правила сохранения словарной фразы.

Сервер проверяет источник, версию и принадлежность сегмента, сам извлекает
исходный абзац с числами, пунктуацией и пробелами. Для кнопки абзаца
`selected_text == context_text`; относительные границы охватывают весь абзац.
Подготовленный снимок и исторические вложения хранят название, язык, версию
источника, token ordinals и source offsets. В новом черновике полный текст
копируется в fenced-блок и затем живёт как обычная редактируемая часть сообщения.
`context_start_offset` и `context_end_offset` — полуоткрытый диапазон в Unicode
code points. Frontend учитывает отличие code points от UTF-16, поэтому emoji
перед цитатой из карточки слова не смещает подсветку.

Снимки неизменны после отправки, включая изменение или удаление материала.
Старые снимки без относительных смещений остаются читаемыми; первое совпадение
не подставляется вместо неизвестного точного вхождения. JSON-экспорт сохраняет
оба nullable относительных смещения вместе с текстом снимка, в том числе после
удаления исходного материала. Переход к источнику
повторно проверяет доступ и версию: старый ordinal используется только при
совпадении версии, удалённый источник не открывается.

Список разговоров общий для самостоятельной страницы `/learn/$lang/chat` и
reader. На широком экране список слева, материал в центре, чат справа.
На узком экране есть отдельный возврат к чтению. История, черновики и снимки
сохраняются; словарь, attribution, SRS и статистика чтения не меняются.

## Состояние и выполнение

- Данные принадлежат авторизованному пользователю, все вложенные ресурсы
  проверяют владельца. История входит в экспорт и hard-delete профиля.
- PostgreSQL хранит conversation, message, citation, draft и generation.
  Worker выполняет запрос независимо от открытой панели. UI опрашивает
  сохранённое состояние активной генерации раз в секунду.
- Черновик использует CAS revision и сериализованную очередь. При конфликте
  сохраняется локальная копия и показываются варианты явного восстановления.
  Ввод во время отправки не стирается её поздним подтверждением. Подготовка
  цитаты принадлежит черновику в общем состоянии: уход из ридера на отдельную
  страницу чата не снимает её блокировку отправки.
- Отправка и retry используют operation UUID. Потерянное подтверждение можно
  повторить независимо от нового текста, включая очищенный composer.
  Обычная новая отправка требует вопроса; одна цитата не запускает модель.
- Активный разговор ограничен пользователем и вкладкой. При выходе очищаются
  память и session fallback; identity epoch отсекает поздние ответы.
- Закрытие панели не является Stop. Явная отмена сохраняет частичный текст.
  Ошибки, прерванная работа и отмена различаются; retry создаёт новую генерацию
  без дублирования исходного вопроса.

## UI-библиотеки и безопасность

Используются закреплённые `@assistant-ui/react@0.15.19`, `react-markdown@10.1.0`
и `remark-gfm@4.0.1`, все MIT. assistant-ui подключён через публичный ExternalStoreRuntime;
Glosano владеет историей, composer и транспортом. Обязательных Assistant Cloud,
cloud credentials, новой авторизации или Node service нет. Наличие
`assistant-cloud` в transitive dependency tree не означает его использование.

Markdown не исполняет raw HTML, очищает URL и заменяет внешние изображения
текстом, не загружая их. Ответы помечены как AI-generated. Новые объяснения
следуют языку UI (EN/RU); исторические сообщения не переписываются.

`ChatMarkdown` оформляет заголовки, списки, цитаты, inline-код и GFM-таблицы.
Fenced-блоки без метки языка в сообщениях пользователя отображаются как цитаты:
обычный шрифт, мягкий фон, полоса слева и перенос длинных строк. Это включает
уже сохранённые цитаты из ADR-0020 без изменения их текста. Блоки кода в ответах
и блоки с указанным языком сохраняют моноширинное оформление и локальный скролл;
широкие таблицы также прокручиваются внутри сообщения.

Исходный текст и сообщения считаются недоверенными данными, а не system
instructions. Логи содержат метаданные, без текста запросов и секретов.
SQL engine скрывает параметры; Loguru не печатает locals через diagnostics.

## Provider contract

Один OpenAI-compatible Chat Completions адаптер использует существующие
`GLOSANO_LLM_*` настройки. При пустом API key Authorization не отправляется.
История содержит только текущий приватный разговор. В JSON пользовательского
сообщения новые цитаты входят прямо в `text`. Исторические сообщения могут
содержать `attachments`: `selected_text`, `context_text`, точные смещения и provenance. System prompt объясняет, что
цитата — предмет вопроса, а весь абзац — его контекст.

По [ADR-0021](../adr/ADR-0021-plain-text-chat-replies.md) SSE `delta.content`
содержит обычный текст или Markdown. Worker сохраняет фрагменты напрямую,
не требует построчных JSON-записей и не выполняет format-repair запрос.
Непотоковый `message.content` обрабатывается так же. История assistant передаётся
обычным текстом. JSON-конверт пользовательского контекста — входные данные,
а не образец формата ответа.

JSON-примеры и fenced code blocks отображаются как текст и не исполняют
exercise/evaluation команды. Пустой ответ отклоняется; общий предел ответа
64000 символов сохраняется, отдельного лимита4000 на абзац нет.

HTTP 400/405/415/422 до вывода допускает fallback `stream:false` с тем же
содержимым. Network/5xx — максимум три HTTP-попытки с backoff0.25/0.5с;
после первого output fragment автоматического повтора нет. SSE требует
`[DONE]`; преждевременный EOF и `finish_reason:length` считаются ошибками.
Общий deadline генерации —180с. Состояние AI проверяется перед внешними вызовами.

## Лимиты

| Настройка с prefix `GLOSANO_` | Default |
| --- | ---: |
| `CHAT_CONTEXT_CHAR_BUDGET` |24000 символов |
| `CHAT_ANSWER_MAX_TOKENS` |1500 |
| `CHAT_MAX_ATTACHMENTS` |4 |
| `CHAT_ATTACHMENT_CHAR_LIMIT` |6000 символов JSON снимка |

Новый черновик допускает16000 символов, включая fenced-цитаты. Для совместимости
старый формат допускает8 вложений; отправка отдельно проверяет
более узкие provider budgets. Снимок ограничен4000 символов выбранного текста
и12000 контекста. Лимиты сообщаются явно: полный абзац не обрезается молча.
Обязательный текущий вопрос и вложения должны помещаться целиком; последние
до100 сообщений добавляются в оставшийся бюджет. Это символьный бюджет,
не точный tokenizer count. `context_truncated` отражает усечение истории.

При `GLOSANO_LLM_ENABLED=false` доступны история, черновики, управление чатами
и Stop, но новые внешние вызовы запрещены. Settings кешируются: изменение
environment требует перезапуска API/worker; отдельной admin UI здесь нет.

## Отложенные упражнения и миграции

В новой версии нет selector формата, интерактивной практики и её действий.
Новые exercise/evaluation команды, их retry и worker-выполнение отклоняются
на сервере. Обычный текстовый вопрос может обсуждать любые языковые примеры;
это не создаёт отдельной сущности упражнения.

Таблицы раннего прототипа и сохранённые данные не удаляются: они остаются
совместимыми с экспортом и hard-delete. Исторические ссылки не должны блокировать
новый текстовый вопрос. Тренажёр слов FLQ-20 и его AI-интеграция не меняются.

Feature migration chain начинается от tracked `0019_youtube_materials`:
`0020_private_chats` → `0021_chat_generation_requests` → `0022_chat_citation_offsets` (точные границы цитаты). Старые migrations
не переписываются. Проверяются upgrade/downgrade feature-only графа и локального
графа с numeric migration из другой задачи.

В текущем checkout numeric migration принадлежит другой незакоммиченной работе.
Совместимость обеспечивает **локальная незакоммиченная** merge revision
`0021_local_chat_numeric_merge.py`. Она не входит в feature commits, чтобы
чистая ветка не зависела от отсутствующего numeric revision. При совместной
интеграции двух задач потребуется включить согласованную merge revision.

объяснений конкретного live provider требует отдельной проверки с его конфигурацией.
