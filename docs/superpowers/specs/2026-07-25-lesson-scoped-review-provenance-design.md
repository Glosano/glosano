# Повторение лексики урока по провенансу: дизайн

- Дата: 2026-07-25
- Основания: FLQ-7 (SRS review engine), FLQ-20 (word trainer), ADR-0005 (статусная модель), domain model §8.2
- Статус: одобрен пользователем (сессия 2026-07-25)

## 1. Проблема

Кнопка «Повторить лексику» в ридере ведёт на `/learn/$lang/review?lessonId=…`. Скоуп технически работает — `lesson_id` доезжает до бэкенда и очередь фильтруется, — но фильтр определяет «лексику урока» как **любое tracked-слово пользователя, чей текст встречается в тексте урока** (join `lesson_token_occurrences.normalized_text = token_items.token_text`).

Замеры на реальной dev-БД пользователя `07e08563`:

| очередь | размер |
|---|---|
| глобальная (en) | 18 |
| урок «Reddit text» (527 вхождений) | 7 |
| урок «AI Text» (1932 вхождения) | 8 |
| урок «Test» (pt, 720 вхождений) | **7 из 7 pt-слов словаря** |

Чем длиннее урок, тем полнее он покрывает словарь: на уроке в 720 токенов повторение урока неотличимо от глобального. Отсюда жалоба «повторяю всё подряд».

Два усугубляющих факта:

1. **`token_items.created_from_occurrence_id` не заполняется ни одним write-путём** — 0 из 592 строк. Поле добавлено миграцией `0009_item_provenance`, читается только в `review/service.py` для контекстного предложения. Следствие: `context_sentence` на карточках всегда `null`.
2. **Фразы исключены из lesson-режима полностью** (документированное MVP-ограничение FLQ-7 §1) — у пользователя 5 tracked-фраз, набранных при чтении этих же уроков, и в повторении урока их нет.

## 2. Решение

«Лексика урока» = **слова и фразы, добавленные пользователем в этом уроке**, а не пересечение словаря с текстом. Провенанс начинает записываться в момент добавления; бэкфилла существующих 592 записей нет (решение пользователя — чистая семантика вместо эвристики).

## 3. Данные (миграция `0014_vocab_lesson_provenance`, `down_revision = "0013_review_quality"`)

В `token_items` и `phrase_items`:

| Поле | Тип | Назначение |
|---|---|---|
| `created_from_lesson_id` | UUID NULL, FK → `lessons(id)` ON DELETE SET NULL | ключ скоупа; переживает переимпорт урока |
| `created_from_segment_id` | UUID NULL, без FK | предложение-источник → контекст на карточке |

Индекс на обеих таблицах: `(user_id, created_from_lesson_id) WHERE created_from_lesson_id IS NOT NULL`.

`token_items.created_from_occurrence_id` удаляется (мёртвая колонка, 0 непустых значений, вытеснена `created_from_segment_id`). `down()` возвращает её nullable, без данных.

Почему сегмент, а не вхождение: `lesson_token_occurrences` и `lesson_segments` пересоздаются при переимпорте урока одинаково, но сегмент уже есть на клиенте (`Sentence.seg_id`), а id вхождения в payload контента не передаётся — чтобы слать вхождение, пришлось бы утяжелить `/content` на UUID на каждый токен (до 1932 токенов на урок).

## 4. Захват провенанса

`POST /api/vocabulary/items` **и** `PATCH /api/vocabulary/items/{kind}/{id}` получают необязательные `lesson_id: UUID | None` и `segment_id: UUID | None`. PATCH обязателен: ридер зовёт `createItem` только когда item'а ещё нет, а повторное взятие в работу уже известного слова идёт через `patchItem` — без провенанса на PATCH такие слова не попадали бы в свой урок.

Валидация (общая для `create_item` и `patch_item`):
- урок не принадлежит пользователю или не существует → 404;
- `segment_id` не принадлежит указанному уроку → 422;
- `segment_id` без `lesson_id` → 422.

Запись:
- при создании нового item'а — оба поля;
- при переводе существующего item'а в `tracked`, **если `created_from_lesson_id IS NULL`** — иначе слово, отмеченное когда-то `known` (или взятое из словаря вне урока), навсегда осталось бы вне повторения урока, в котором его реально начали учить;
- уже проставленный провенанс не перезаписывается: первый урок выигрывает.

`reader_state/bulk.bulk_mark_known` проставляет `created_from_lesson_id` создаваемым `known`-item'ам: провенанс честный, и при последующем re-track слово попадёт в свой урок.

Ридер:
- `ReaderPage` вычисляет `selectedSegId` тем же поиском по `flatSentences`, что и существующий `selectedSentenceText` (для фраз — из `sentence.seg_id` в `handlePhraseSelect`/`handlePhraseClick`), и передаёт в `WordCard` → `useWordCard`;
- `vocabularyApi.createItem` и `vocabularyApi.patchItem` получают `lesson_id`/`segment_id` в теле; `useWordCard` передаёт их в обеих мутациях; вне ридера (страница словаря) поля не передаются.

## 5. Очередь и счётчики

`review/service.get_queue(..., lesson_id=…)`:
- джойн по `lesson_token_occurrences` убирается; условие — `model.created_from_lesson_id == lesson_id` для **обоих** видов (`token` и `phrase`);
- владение уроком по-прежнему проверяется до запроса (`LessonNotFound` → 404);
- порядок прежний: сначала due, затем по `due_at`; дневной лимит в lesson-режиме не применяется (`limit_reached = false`).

Тот же фильтр добавляется в режимы `new` (`last_reviewed_at IS NULL`) и `practice` (`confidence >= 4`), то есть `lesson_id` становится ортогонален `mode`, а не альтернативой ему.

`GET /api/review/counts` получает необязательный `lesson_id` и считает `due`/`new`/`practice` в том же скоупе (валидация урока та же). `ai_enabled` не зависит от скоупа.

Контекстное предложение в `_build_queue_items` читается из `created_from_segment_id → lesson_segments.text` — для токенов и для фраз.

## 6. Экран

Из ридера открывается тот же экран выбора режима, что и из словаря, но в скоупе урока:

- `ReviewPage`: `lessonId` больше не шунтирует сразу в карточки; при `lessonId && !mode` показывается `ModeSelect` с подзаголовком «Слова урока»;
- `ModeSelect` принимает `lessonId`, запрашивает `counts` с ним и сохраняет его в `search` при переходе в режим;
- все пять сессий (`cards`, `new`, `cloze`, `reverse`, `translation`) принимают `lessonId` и передают в `useReviewSession`; ключ запроса уже включает `lessonId`;
- пустой экран режима в lesson-скоупе: «В этом уроке ты пока не добавил слов» + кнопка «Повторить весь словарь» → `/learn/$lang/review` без `lessonId`;
- AI-упражнения (`/exercise`) работают по `review_item_id` и скоупа не знают — правок не требуют.

На уроках, прочитанных до релиза, повторение будет пустым, пока в них не добавят слова: провенанса у старых записей нет по решению «не бэкфиллить».

## 7. Тесты

Бэкенд:
- `create_item` пишет `lesson_id`/`segment_id`; чужой урок → 404; сегмент из другого урока → 422; `segment_id` без `lesson_id` → 422;
- re-track существующего `known`-слова через PATCH проставляет провенанс, если он пуст, и не перезаписывает непустой;
- `bulk_mark_known` проставляет урок;
- очередь урока: содержит слово и **фразу**, добавленные в этом уроке; не содержит слово, добавленное в другом уроке, даже если его текст встречается в этом; не содержит слово без провенанса;
- `mode=new`/`practice` в связке с `lesson_id`;
- `counts` с `lesson_id`;
- `context_sentence` приходит из сегмента (регрессия на мёртвый провенанс).

Фронтенд:
- ридер шлёт `lesson_id`/`seg_id` при добавлении слова и фразы;
- `ModeSelect` в lesson-скоупе запрашивает счётчики с `lessonId` и сохраняет его при переходе в режим;
- пустой экран урока показывает кнопку на глобальное повторение.

## 8. Вне скоупа

- Бэкфилл провенанса существующих записей.
- Провенанс для слов, добавленных вне ридера (страница словаря, импорт словаря) — остаётся `NULL`.
- Счётчик слов урока на кнопке «Повторить лексику» в ридере.
- Пересчёт провенанса при переимпорте урока (сегмент пересоздаётся → контекст может стать пустым; `created_from_lesson_id` не страдает).
