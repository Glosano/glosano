# Прогресс чтения в карточке библиотеки: дизайн

- Дата: 2026-07-25
- Основания: FLQ-8 (Stats page), `docs/ui/library.md` §8.1, domain model §7.1 (`reader_positions`), §12.2 (`lesson_progress`)
- Статус: одобрен пользователем (сессия 2026-07-25)

## 1. Проблема

В библиотеке карточка любого урока показывает `0%` — всегда, у всех документов, независимо от того, читал пользователь урок или нет.

Это не ошибка вычисления: величина не вычисляется нигде.

1. `frontend/src/features/library/LessonCard.tsx:21,24` — процент захардкожен: `style={{ width: '0%' }}` и текст `0% · {word_count} слов`.
2. `LessonSummary` (`backend/src/flinq/modules/lesson_library/schemas.py`) не содержит поля прогресса — бэкенд его не отдаёт.
3. Таблицы `lesson_progress` (domain model §12.2) в бэкенде нет: ни модели, ни миграции. Она запланирована в невыполненной FLQ-8, от которой карточка библиотеки де-факто зависела.

## 2. Что именно показывать

`docs/ui/library.md:140` описывает бар как **coverage** — `known_occurrence_count / occurrence_count`, «какая доля текста тебе знакома». Пользователь запросил другое: **долю прочитанного текста**.

Это разные величины с разным поведением. Coverage дочитанного урока с незнакомой лексикой останется низким; позиция чтения будет 100%. И наоборот: новый урок со знакомой лексикой откроется сразу с высоким coverage при нулевой позиции.

**Решение: карточка показывает позицию чтения, не coverage.** Спека библиотеки §8.1 в этой части считается устаревшей и правится по факту.

Карточка несёт три числа:

| Число | Источник | Единицы |
|---|---|---|
| `% прочитано` | `reader_positions.current_token_ordinal / MAX(ordinal_in_lesson)` | — |
| `слов` | `lessons.word_count` (уже есть) | словоупотребления |
| `новых` | уникальные слова без `TokenItem` **на остатке текста** | уникальные слова |

Разные единицы у второго и третьего числа — осознанно: «сколько слов в тексте» естественно считать вхождениями, «сколько предстоит выучить» — уникальными. Так же устроен LingQ.

## 3. Принятые решения

### 3.1 Позиция, а не максимум по истории

Процент падает при возврате назад. Урок дочитан до конца, пользователь открыл первую страницу перечитать — карточка покажет ~3%.

Альтернатива (high-water mark) отвергнута: она рассинхронизирует карточку с кнопкой возврата. Карточка говорила бы «100% прочитано», а «продолжить» открывало бы первую страницу. Это ровно тот класс несогласованности, с которого начался баг.

### 3.2 Новые слова считаются в уникальных словах

`casa` пять раз на остатке — это **одно** новое слово. Подпись отвечает на вопрос «сколько работы осталось», повторы для этого не нужны.

### 3.3 Якорь — начало текущей страницы (`fromOrdinal`)

В ридере живут два разных ординала:

- `ReaderPage.tsx:127-137` — бар считает по **концу** текущей страницы (`currentPage.toOrdinal`);
- `ReaderPage.tsx:329-330` — в БД пишется **начало** страницы (`currentPage.fromOrdinal`), потому что это якорь resume: вернуться нужно в начало недочитанной страницы.

Карточка считает от сохранённого `current_token_ordinal`, то есть от `fromOrdinal`. Обоснование: страницу, на которой стоишь, ты ещё не прочитал, а для «новых слов на остатке» этот якорь единственно верный — слова текущей страницы ещё впереди. Оба числа карточки берутся из одного ординала.

Следствие, принятое сознательно: бар в библиотеке отстаёт от бара в ридере на одну страницу — на последней странице ридер покажет 100%, библиотека ~90%. Выравнивание бара ридера (чтобы он тоже считал от начала страницы) выносится отдельной задачей; согласованность достигается упрощением ридера, а не вторым полем в БД.

### 3.4 Считаем на лету, `lesson_progress` не создаём

«Новое слово» — это отсутствие `TokenItem` у пары (user, language, token_text). Признак **не принадлежит уроку**: пометив `casa` известным в уроке A, пользователь обязан увидеть уменьшившийся счётчик новых слов во всех уроках языка, где `casa` встречается. Это подтверждённое пользователем требование, а не побочный эффект.

Денормализованные счётчики `lesson_progress` пришлось бы инвалидировать веером по всем задетым урокам при каждом изменении статуса слова — а таких точек записи четыре:

- `vocabulary/service.py` (~289–381) — сохранение из WordCard;
- `vocabulary/service.py:984` — bulk `set_known` / `set_ignored` / `delete`;
- `reader_state/bulk.py:56,102` — «знаю всю страницу» и undo;
- `review/service.py:405` — graduation в `known` после SRS.

Плюс остаток новых слов зависит от позиции чтения, которая меняется при каждом перелистывании. Хранимый счётчик здесь — источник рассинхронизации без выигрыша.

**Поэтому: ни новых таблиц, ни миграций.** Один агрегат на страницу списка.

## 4. Архитектура

### 4.1 Запрос

Один запрос на страницу списка (≤ `page_size`, по умолчанию 25 уроков):

```sql
SELECT o.lesson_id,
       MAX(o.ordinal_in_lesson)      AS max_ordinal,
       MAX(rp.current_token_ordinal) AS position,
       COUNT(DISTINCT o.normalized_text) FILTER (
           WHERE ti.id IS NULL
             AND o.ordinal_in_lesson > COALESCE(rp.current_token_ordinal, -1)
       )                             AS new_remaining
  FROM lesson_token_occurrences o
  LEFT JOIN reader_positions rp ON rp.lesson_id = o.lesson_id AND rp.user_id = :user
  LEFT JOIN token_items ti      ON ti.user_id = :user
                              AND ti.language_code = :lang
                              AND ti.token_text = o.normalized_text
 WHERE o.lesson_id = ANY(:page_ids) AND o.is_word_like
 GROUP BY o.lesson_id
```

`rp` соединяется один-к-одному по уникальному `(user_id, lesson_id)` (`uq_reader_positions_user_lesson`), поэтому `MAX(rp.current_token_ordinal)` — способ протащить позицию через `GROUP BY`, а не настоящая агрегация.

Ни один из двух `LEFT JOIN` не размножает строки: `reader_positions` уникален по `(user_id, lesson_id)`, `token_items` — по `(user_id, language_code, token_text)` (`uq_token_items_user_lang_text`). Поэтому `COUNT(DISTINCT …) FILTER` считает то, что заявлено, а не удвоенное.

Индексы, на которые опирается запрос, уже есть: `lesson_token_occurrences.lesson_id`, `lesson_token_occurrences.normalized_text`, `ix_token_items_user_lang`.

Система координат едина: `i` в проводном контракте ридера — это `ordinal_in_lesson` (`reader_state/content.py:69`), и позиция, знаменатель и фильтр остатка выражены в нём же.

### 4.2 Размещение кода

Новый модуль `backend/src/flinq/modules/lesson_library/progress.py` с единственной публичной функцией:

```python
async def progress_for_lessons(
    session: AsyncSession, *, user_id: uuid.UUID, lang: str, lesson_ids: Sequence[uuid.UUID]
) -> dict[uuid.UUID, LessonProgress]
```

`api/lessons.py::list_lessons` вызывает её один раз после `LessonRepo.list_for_user` и склеивает результат с DTO. Уроки, отсутствующие в ответе (нет ни одного word-like токена), получают нули.

Отдельный модуль, а не метод репозитория: это чтение через границу трёх агрегатов (`Lesson`, `ReaderPosition`, `TokenItem`), тогда как `LessonRepo` работает только с агрегатом `Lesson`.

### 4.3 Контракт

`LessonSummary` (backend + `frontend/src/api/lessons.ts`) получает два поля:

- `read_percent: int` — 0..100;
- `new_words_remaining: int` — ≥ 0.

Оба неотрицательные и всегда присутствуют, чтобы фронт не ветвился на `null`.

### 4.4 Формула процента

Повторяет ридер (`ReaderPage.tsx:133-137`) один в один, включая вырожденные случаи:

```
position is None или max_ordinal is None  -> 0
max_ordinal == 0                          -> 100
иначе                                     -> clamp(round(position / max_ordinal * 100), 0, 100)
```

## 5. Краевые случаи

| Случай | Поведение |
|---|---|
| Урок ни разу не открывали (нет строки `reader_positions`) | 0%, новых = все уникальные слова урока, которых нет в словаре пользователя |
| Урок без word-like токенов | 0%, новых 0 (в агрегате строки нет) |
| Урок из одного слова (`max_ordinal == 0`) | 100% |
| `current_token_ordinal IS NULL` при существующей строке позиции | 0%, остаток = весь текст |
| Позиция за пределами урока после переимпорта текста | `clamp` до 100%, остаток 0 |
| Все слова урока известны | процент по позиции, новых 0 |
| Слово помечено known в другом уроке | новых уменьшается здесь немедленно |

## 6. Тестирование

**Бэкенд** — API-тесты на `GET /api/lessons` (`backend/tests/api/test_lessons.py`):

- урок без позиции → `read_percent == 0`, `new_words_remaining` равен числу уникальных слов;
- наполовину прочитанный урок → процент в ожидаемом диапазоне, остаток меньше полного;
- дочитанный до последнего слова → 100%;
- урок без словоформ → нули, отсутствие падения;
- слово помечено `known` в другом уроке того же языка → `new_words_remaining` этого урока уменьшился;
- `known`-слово другого языка не влияет на счётчик (языковая изоляция).

Юнит-тесты формулы процента — на вырожденные случаи из §5.

**Фронтенд** — новый `frontend/src/features/library/LessonCard.test.tsx`:

- ширина бара соответствует `read_percent`;
- отрисованы все три числа;
- урок с нулевым прогрессом не ломает вёрстку.
