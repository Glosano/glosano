# FLQ-28 — Проверка импорта YouTube

- Дата: 2026-09-16.
- Задача: FLQ-28.1.
- Проверено: названия, список дорожек, текст и временные интервалы субтитров.
- Приложение и его зависимости не изменялись. Видео/аудио не скачивались.

## Метод

В отдельном временном окружении `uv` установлены
`youtube-transcript-api==1.2.4` и `yt-dlp==2026.8.19`.
В живой проверке использован первый пакет; yt-dlp установлен для сравнения,
но запросы через него не выполнялись.

Название и автор получены через
`https://www.youtube.com/oembed?url=<canonical-video-url>&format=json`.
Дорожки получены вызовом `YouTubeTranscriptApi.list(video_id)`, затем
выбранная дорожка прочитана через `fetch().to_raw_data()`.
Использованы обычные HTTPS-запросы без API-ключей, входа в YouTube,
браузерных cookies и специально настроенного прокси.
Таймауты соединения/чтения — 10/20 секунд.

Первый запуск в файловой песочнице не смог разрешить DNS для PyPI.
Повтор с разрешённым сетевым доступом установил пакеты и выполнил запросы.
Это ограничение среды проверки, а не отказ YouTube.

## Вывод для дизайна

Для первого адаптера достаточно `youtube-transcript-api` и oEmbed.
Название, автор, язык, тип дорожки, текст, start/duration получены независимо
от AI-провайдера. Текущая проверка подтверждает работоспособность на этом
компьютере и этих роликах, а не на любом сервере и любом видео.

Субтитры — последовательность временных реплик. Реплика может содержать
часть предложения или несколько предложений. Частые перекрытия автоматических
дорожек нельзя трактовать как основание объединить все пересекающиеся реплики:
так почти весь ролик превратится в один фрагмент. Нужна отдельная детерминированная
нормализация временных границ, с сохранением исходных интервалов.

## Сравнение вариантов

| Вариант | Польза | Ограничение | Решение |
|---|---|---|---|
| `youtube-transcript-api` + oEmbed | Нужные данные без загрузки медиа; проверено выше | Зависит от неофициального получения субтитров и доступности YouTube | Рекомендуется для первого адаптера |
| `yt-dlp`, только метаданные/субтитры | Больше форматов и возможностей работы с источником | Для текущего сценария более широкий инструмент; живая проверка не выполнена | Резерв для отдельного пересмотра адаптера |
| Официальный `captions.download` | Документированный API | Требует права редактировать видео | Не покрывает импорт обычного чужого публичного ролика |

У `youtube-transcript-api` документированы блокировки IP, в том числе у
облачных серверов. Приложение должно показывать отказ источника отдельно от
отсутствующих субтитров. Эта задача не обещает обход ограничений YouTube.
Если целевая инсталляция получает отказ, импорт нельзя обозначать успешным.

## Ограничения проверки

- Не проверялись все десять языков, целевой Docker-хост, мобильные браузеры
  и управление реальным встроенным плеером.
- Не измерялась точность остановки по звуковой дорожке.
- Не проверялись приватные, возрастные, регионально ограниченные видео,
  прямые эфиры и запрещённое владельцем встраивание.
- Успех получения субтитров не подтверждает доступность встраивания видео.
- Тексты дорожек не включены в репозиторий. Для автоматических тестов нужны
  небольшие синтетические примеры, а для приёмки — отдельный live smoke-test.
